# QA Bugs Spec — 2026-05-26

Сводная спецификация багов, найденных QA-армией суб-агентов на проде https://coach-ai.ru.
Базовый URL: `https://coach-ai.ru/api/v1`. Email verification на момент тестов отключена в `/opt/ai-trainer/.env` (бэкап `.env.bak.before-verif-off`).

Условные обозначения приоритета:
- **P0** — критично для безопасности или базовой целостности данных, чинится первым
- **P1** — важная функциональность сломана / валидация отсутствует / UX-блокер
- **P2** — мелкие неточности, рассогласования API, не критично для пользователя

В каждом баге: где, как воспроизвести, что должно быть, и какие файлы трогать.

## P0 — критичные

### P0-1. `log_exercise_set` не проверяет ownership

- **Endpoint:** `POST /api/v1/workouts/exercises/{workout_exercise_id}/log`
- **Файл:** `backend/app/routers/workouts.py` (функция `log_set`, ~строка 182)
- **Repro:**
  1. user1 создаёт план и получает `workout_exercise_id`
  2. user2 логинится и шлёт `POST /workouts/exercises/{user1_we_id}/log` с `{"set_number":99,"reps_completed":1,"weight_kg":1}` под своим токеном
  3. → 200, set записан в чужой план user1; виден в `GET /workouts/plans/{user1_plan}` под user1
- **Что должно быть:** 404 (либо 403). Любой залогиненный юзер не должен иметь права писать в чужие тренировки.
- **Fix:** в запросе на поиск `WorkoutExercise` сделать join `WorkoutExercise → WorkoutSession → WorkoutPlan` и фильтровать `WorkoutPlan.user_id == current_user.id`. Если не найдено — `NotFoundError`.

### P0-2. Cross-user leakage в `/analytics/dashboard`

- **Endpoint:** `GET /api/v1/analytics/dashboard`
- **Файл:** `backend/app/routers/analytics.py` (функция `dashboard` — расчёт `workouts_this_week`, `streak_days`)
- **Repro:**
  1. Зарегистрируй user1 и user2, оба без логов и тренировок
  2. `GET /analytics/dashboard` под обоими токенами
  3. Оба видят `workouts_this_week=1` (у обоих 0 подходов)
- **Что должно быть:** оба видят 0; счётчики тренировок и streak считаются только по подходам/`ScheduledWorkout` текущего юзера.
- **Fix:** во всех `select(func.count(...))` для `workouts_this_week` и `streak_days` добавить join до `WorkoutPlan.user_id == current_user.id` (или фильтр по `ExerciseSet → WorkoutExercise → WorkoutSession → WorkoutPlan.user_id`).

### P0-3. `/files/upload` принимает любой контент с заявленным `image/*`

- **Endpoint:** `POST /api/v1/files/upload`
- **Файл:** `backend/app/routers/files.py`
- **Repro:**
  1. Создай файл `notimage.txt` с текстом
  2. `curl -F "file=@notimage.txt;type=image/jpeg" -F "folder=avatar"` под валидным токеном
  3. → 200, файл доступен по `/uploads/avatar/<user>/<uuid>.jpg` с текстовым содержимым
- **Что должно быть:**
  1. Проверка magic-bytes (не доверять `Content-Type` клиента)
  2. Открыть через Pillow и пере-сохранить (нормализация)
  3. `folder` — allowlist (`avatar`, `meals`, `progress`)
  4. Запретить `..`, `/`, и любые служебные символы в `folder`
- **Fix:**
  - В `routers/files.py`: после чтения байтов — `PIL.Image.open(BytesIO(data)).verify()`, перенаправить расширение по реальному формату
  - Сделать `_ALLOWED_FOLDERS = {"avatar", "meals", "progress"}` и `if folder not in _ALLOWED_FOLDERS: raise BadRequestError(...)`
  - Вместо склейки — собирать путь из проверенных кусков; никаких `os.path.join(folder, ...)` где folder — от юзера

### P0-4. `Anthropic agent stream failed` после tool_result

- **Endpoint:** `POST /api/v1/chat/conversations/{id}/messages` (SSE), `POST /api/v1/chat/proposals/{id}/approve` (SSE)
- **Файл:** `backend/app/services/ai/agent_engine.py`, `backend/app/services/ai/provider.py:296-299`
- **Repro:** в любом из 60% случаев после успешного `tool_result.ok=true` следующий запрос к Anthropic в том же стриме возвращает ошибку, и в SSE приходит `{"type":"error","message":"Anthropic agent stream failed"}` вместо итогового текста. Tool side-effect применяется к БД, но финальный ответ модели обрублен.
- **Дополнительный симптом:** в новом запросе того же диалога модель не видит результат прошлого tool и предлагает повторно тот же tool (например, повторно `generate_workout_plan` после успешного создания плана).
- **Fix (4 части):**
  1. В `provider.py` логировать **полный** exception из Anthropic SDK с типом и payload запроса (минимум типа исключения и status_code), чтобы понять, валится ли это на 5xx, на bad-tool-result, или на rate-limit.
  2. Persist `ChatMessage` (assistant text accumulated так далеко) и `AgentToolCall.status='approved'` + `result_summary` в БД **до** следующего запроса к Anthropic. Сейчас при стрим-ошибке `db.rollback()` теряет накопленный текст и tool_result не сохраняется в `ChatMessage`-истории.
  3. Авторетрай на агентном пути с экспоненциальным backoff (jitter), 1-2 ретрая. ~60% «failed»-стримов проходят со второго раза.
  4. Сделать SSE-ивент `{"type":"error","retryable":true,"code":"anthropic_stream"}` чтобы фронт мог показать кнопку retry, а не молча оборвать сообщение.

## P1 — важные

### P1-5. `POST /auth/logout` не отзывает refresh token в БД

- **Endpoint:** `POST /api/v1/auth/logout`
- **Файл:** `backend/app/routers/auth.py` (функция `logout`)
- **Repro:**
  1. Login → получить `refresh_token` cookie
  2. Logout (cookie очищается)
  3. Replay этого же `refresh_token` в `POST /auth/refresh` (через body)
  4. → 200 с новым access — старый refresh всё ещё валиден
- **Что должно быть:** после logout запись в `refresh_tokens` помечается `revoked=True` или удаляется. Replay → 401.
- **Fix:** в `logout` читать refresh из cookie (или body), хешировать SHA-256, найти в `refresh_tokens` и удалить/пометить revoked. Транзакция, idempotent.

### P1-6. Регистрация принимает любой пароль

- **Endpoint:** `POST /api/v1/auth/register`
- **Файл:** `backend/app/schemas/auth.py` (`UserRegister.password`)
- **Repro:** `POST /auth/register` с `password=""`, `password="a"`, `password="123"` → 200.
- **Что должно быть:** минимум 8 символов, хотя бы 1 буква + 1 цифра. 422 на нарушение.
- **Fix:**
```python
from pydantic import Field, field_validator

class UserRegister(BaseModel):
    password: str = Field(min_length=8, max_length=128)

    @field_validator("password")
    @classmethod
    def _strength(cls, v: str) -> str:
        if not any(c.isdigit() for c in v) or not any(c.isalpha() for c in v):
            raise ValueError("password must contain letters and digits")
        return v
```

### P1-7. Отсутствует Content-Security-Policy

- **Файл:** `frontend/next.config.ts` (или `next.config.mjs`) или `frontend/middleware.ts`

```ts
    }]
  }];
}
```
Точные источники нужно подобрать по реальным внешним загрузкам.
